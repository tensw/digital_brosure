## 2. 배포 방법

```bash
cd /Users/karis/dev/bibloai-homepage
git pull --rebase origin main        # 다른 세션이 먼저 올렸을 수 있다
git add v2/2026/<고친파일>            # git add -A 금지
git commit -m "..."
git push origin main                 # ← 배포 시작
```

푸시하면 GitHub Actions 가 EC2 에 접속해 `git reset --hard origin/main` 후 `pm2 restart biblo-ai` 를 돌린다. **CLI 로 서버에 직접 올리지 않는다.**

반영까지 **30초~1분**. 확인은 이렇게 한다.

```bash
for i in 1 2 3 4 5; do
  s=$(curl -s -m 15 https://biblo.ai/2026/ | grep -c "<찾을 문자열>")
  [ "$s" != "0" ] && { echo "배포 반영"; break; }; sleep 15
done
```

서버 접속 정보(EC2 호스트·SSH 키)는 저장소에 없다. GitHub 저장소 시크릿(`EC2_HOST`, `EC2_SSH_KEY`)에 있고 코드에서 볼 수 없다.

## 4. 슬라이드 구성 (현재 8장)

`v2/2026/index.html` 안 `window.SLIDES_2q6r4` 배열 **한 곳만 고치면** 순서와 개수가 바뀐다.

```js
window.SLIDES_2q6r4=[
 {kind:'node', id:'sl-cover-8j3v', bg:'cover', name:'표지'},
 {kind:'frame',src:'biblo-solution-6.html', bg:'own', name:'6개 솔루션'},
 {kind:'frame',src:'bk21-data-pool.html',  bg:'own', name:'데이터 풀'},
 {kind:'frame',src:'biblo-search.html',    bg:'own', name:'검색'},
 {kind:'node', id:'sl-hero-2q6r4',  bg:'wave', name:'데이터로 움직이는 AI도서관'},
 {kind:'frame',src:'도서추천_카드.html',      bg:'own', name:'도서 추천 카드'},
 {kind:'node', id:'sl-five-2q6r4',  bg:'wave', name:'다섯 갈래로 나뉜 하나의 데이터'},
 {kind:'node', id:'sl-stats-2q6r4', bg:'wave', name:'실측 규모'}
];
```

| 필드 | 뜻 |
|---|---|
| `kind:'node'` | `index.html` 안에 직접 들어 있는 슬라이드. `id` 로 요소를 지정 |
| `kind:'frame'` | 별도 html 파일을 iframe 으로 끼움. `src` 는 **같은 폴더 기준 상대경로** |
| `bg` | 배경 레이어 키. `'own'` 은 그 파일이 배경을 스스로 그린다는 뜻 |
| `name` | 목록에 뜨는 이름 |

### 슬라이드 추가 절차

```bash

# 2. index.html 의 배열에 한 줄 추가 (원하는 자리)
#    {kind:'frame',src:'새이름.html', bg:'own', name:'표시이름'},
# 3. node server.js 로 확인 → 4. commit → push
```

## 5. 슬라이드 파일 규격

한 장은 **1600×900 무대**를 화면 크기에 맞춰 확대·축소한다. 두 장이 같은 규격이라야 글자 크기와 좌우 여백이 일치한다.

```css
html,body{overflow:hidden}
.slide{position:relative;width:100vw;height:100vh;overflow:hidden}
#stage{position:absolute;left:50%;top:50%;width:1600px;height:900px;transform-origin:50% 50%}
.wrap{width:1600px;height:900px;padding:38px 82px 16px}   /* 좌우 82px 고정 */
```

```js
function fitStage(){
  const st=document.getElementById('stage'), SH_=900;
  st.style.height=SH_+'px';
  const k=Math.min(innerWidth/1600, innerHeight/SH_);
  st.style.transform=`translate(-50%,-50%) scale(${k.toFixed(4)})`;
}
fitStage();
addEventListener('resize',fitStage);
addEventListener('load',fitStage);
addEventListener('pageshow',fitStage);
if(window.ResizeObserver) new ResizeObserver(fitStage).observe(document.documentElement);
if(document.fonts&&document.fonts.ready) document.fonts.ready.then(fitStage);
```

`resize` 하나만 걸면 **iframe 슬라이드에서 배율이 틀어진 채 굳는다.** 지연 로딩으로 화면 밖에서 먼저 계산되기 때문이다. 위 다섯 개를 다 건다.

### 폰트·크기 규칙

```css
body{font:14px/1.6 "Pretendard","Apple SD Gothic Neo",-apple-system,BlinkMacSystemFont,system-ui,sans-serif}
```

**순서가 중요하다.** `-apple-system` 을 앞에 두면 이 맥에서 다른 글꼴로 렌더돼 같은 px 인데 크기가 달라 보인다.

| 요소 | 값 |
|---|---|
| 제목 (라틴) | `4em` (= 56px) |
| 제목 (한글) | `3.15em` (= 44px) |
| 서브 문구 | `16px / 600` |
| 카드 타이틀 | `15px / 800 / 자간 -.4px` |
| 카드 본문 | `14.5px / 500 / 행간 1.5` |

한글은 라틴 대문자보다 자면을 크게 채운다. **같은 px 를 주면 한글이 3할쯤 커 보인다.** 그래서 제목만 값이 다르다.

### CSS 이름 충돌 방지

한 파일 안의 클래스·id·CSS 변수에는 **파일마다 다른 2~4자 접미사**를 붙인다. iframe 이 아닌 `node` 슬라이드로 옮길 때 충돌한다.

```
index.html            -8j3v
biblo-search.html     -7q2v8
```

## 6. 밟았던 함정 (같은 실수 반복 금지)

### 6-1. 주소 끝 슬래시

`biblo.ai/2026` (슬래시 없음) 로 들어오면 문서 안 상대경로가 **상위 폴더 기준**으로 잡혀 iframe 이 전부 깨진다. `server.js` 가 301 로 `/2026/` 을 붙이도록 고쳐 뒀다. 새 폴더를 만들어도 자동 적용된다.

### 6-2. 없는 경로

예전에는 없는 경로가 전부 대문(학술정보관 브로슈어)으로 떨어져 **200 을 반환**했다. 오타 주소가 멀쩡한 페이지처럼 보여 한참 헤맸다. 지금은 404 를 준다. 되돌리지 마라.

### 6-3. 브라우저 캐시

HTML 응답에 `Cache-Control: no-cache, must-revalidate` 를 붙여 뒀다. 그래도 옛 화면이 보이면 `?x=1` 을 붙여 확인한다. 시크릿 창도 그 세션 안에서는 캐시가 남는다.

### 6-4. `position:fixed` 와 무대

무대(`#stage`)에 `transform` 이 걸려 있어서, **그 안의 `position:fixed` 는 화면이 아니라 무대를 기준으로 잡힌다.** 화면 하단에서 올라오는 팝업 같은 요소는 무대 **밖**에 둔다.

```html
</div></div>            <!-- 무대 닫기 -->
<div class="panel" id="panel"></div>   <!-- 팝업은 여기 -->
```

### 6-5. 요소를 지울 때

문구를 지우겠다고 **요소째 삭제하면 JS 가 죽는다.** 검색 슬라이드에서 하단 캡션 요소를 지웠더니 레이아웃 함수가 그 요소 높이를 읽다가 멈춰, 글로우가 사라지고 추천 알약이 화면 위로 튀었다. **요소는 남기고 내용만 비운다.** 지우기 전에 `grep` 으로 JS 참조를 확인한다.

### 6-6. 파일마다 다른 헬퍼

SVG 요소 생성 헬퍼 `el()` 의 시그니처가 파일마다 다르다.

```js
// bk21-data-pool.html — 부모를 받지 않는다. 직접 appendChild 해야 한다
const el=(t,a={})=>{...; return e;};
// 다른 파일 — 세 번째 인자로 부모를 받는다
function el(t,a,p){...; (p||sc).appendChild(e); return e;}
```

세 번째 인자를 넘겼다가 조용히 무시돼 텍스트가 통째로 안 나온 적이 있다. **쓰기 전에 정의를 확인한다.**

### 6-7. 수치는 실측만

화면에 적는 숫자는 DB 에서 직접 잰 값만 쓴다. 문서에서 베끼지 않는다. 재는 방법은 `docs/` 의 BIBLO 문서군과 Supabase MCP 참고. 잰 값과 기준일을 같이 적는다.
