01 · 지난 이관

지난 이관에서 확인된 것

네 가지 확인 사항이 있다. 당시 공유된 정보와 판단 경위는 추가 확인이 필요하며, 여기서는 기록과 실측으로 확인된 상태만 적는다.

작성 2026-09-14 · 대상 개발·운영 전원
책임자 선임연구원 김경수
확인 1 · 기능 이관
화면은 재현했고, API(창구)는 없었다
구 관리자 22화면을 화면 기준으로 재현했다. 사서 업무 5종(정기교육 개설 · 스터디룸 방 설정 · 사물함 신설 · 지정도서 등록 · 포인트 관리)은 쓰기 API가 없어 저장할 곳이 없는 상태였다.
확인 2 · 외부 연계
화면에 보이지 않던 의존
구 시스템이 자기 백엔드를 lib.ptu.ac.kr 이름으로 부르고 있었고, dCollection(논문 제출)도 같은 주소로 인증을 요청하고 있었다. 9/9 주소 전환 직후 검색·소장·로그인·스터디룸과 논문 제출 인증이 실패했다.
확인 3 · 위험 기록의 활용
위험은 기록되어 있었다
8/21 · 8/26 · 9/5 문서 3건에 관리자 API 미제공과 미조치 항목이 기재되어 있다. 이 기록이 오픈·전환 판단에 어떻게 사용되었는지는 확인이 필요하다.
확인 4 · 종료 범위
「종료」의 범위가 정의되지 않았다
문서에는 9/8 종료로 기재되어 있다. 9/14 실측에서 구 시스템은 weblib.ptu.ac.kr에서 동작 중이었다. 문서상 종료가 무엇을 뜻했는지 확인이 필요하다.
현재 상태 · 9/14
서비스는 응답한다. 임시 릴레이 2개를 사용 중이며, 관리자 18개 화면은 인포테크 API 제공 대기 상태다. 응답 확인은 업무 기능의 정상 작동을 뜻하지 않는다.
논의 질문이 네 항목 중 실제 업무 영향이 충분히 설명되지 않은 부분은 무엇입니까?
