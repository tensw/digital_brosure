8도메인 전환 시 발생한 장애

2026-09-09 도메인 전환 후 구 시스템의 검색·소장·로그인·스터디룸 기능에서 실패가 발생했다. 구 홈페이지를 이용하던 이용자도 영향을 받았다.

기록된 원인

구 시스템의 Libraapi는 자기 내부 백엔드를 http://lib.ptu.ac.kr/OdisuService/… 라는 주소로 호출하고 있었다. 해당 주소가 신규 시스템으로 연결되면서 구 서버가 백엔드를 찾지 못했다. 오류 메시지는 「수신 대기 중인 끝점이 없습니다」였다.

같은 원인으로 다음 날 dCollection(본교 논문 제출)의 인증이 실패했다. dCollection은 도서관 인증 API를 lib.ptu.ac.kr/Libraapi/user/usrauth 주소로 호출하고 있었다.

두 건 모두 신규 시스템 화면에는 나타나지 않는 의존 관계다. 화면 점검 외에 호출 설정과 연계 시스템의 동작을 별도로 확인해야 발견할 수 있다.

조치는 nginx에 릴레이 두 개를 추가해 해당 경로의 요청을 구 서버로 전달하는 것이었다. 릴레이는 호출 주소가 weblib로 변경되기 전까지 유지하는 임시 조치이며, 정식 해결에는 인포테크와 KERIS의 설정 변경이 필요하다.

  1. 작업 정의목적, 포함 범위, 제외 범위, 산출물, 완료 기준. 「홈페이지를 옮긴다」가 아니라 「구 시스템 이용자 메뉴 63건을 신규 화면으로 대체한다」처럼 경계가 드러나게 기재한다.
  2. 영향범위화면·데이터·파일·외부 연계·사람·복구 가능성. §13 점검표로 항목별 확인.
  3. 업무 영향실패하거나 지연될 경우 영향받는 사용자, 업무 담당자, 외부 기관을 각각 기재한다.
  4. 외부 의존 사항다른 담당자·기관의 제공 또는 승인이 필요한 사항. 무엇을, 누가, 언제까지, 확보되지 않을 경우의 처리까지.
  5. 보류 조건과 판단 담당자어떤 조건이 충족되지 않으면 진행하지 않는지, 그 판단을 누가 하는지. 필수 기재 항목이다.

15전환·종료 작업의 추가 기준

기존 시스템을 종료하거나 주소를 이전하는 작업은 다음 조건의 검증 결과와 승인 기록이 확보된 후 실행한다.

확인 항목기준
잔여 항목 처리필수 통과 항목과 조건부 승인 가능 항목을 구분한다. 조건부로 진행하는 항목은 업무 영향, 대체 운영 방안, 조치 담당자, 기한, 예외 승인자를 기록한다
외부 호출 확인연계 기관·외부 시스템의 설정에 우리 주소가 등록되어 있는지 확인한다. 접근 권한이 없으면 상대 담당자의 설정 확인 자료와 연계 시험 결과를 확보한다
회신과 검증 구분회신 내용, 제공 완료, 연계 시험 결과, 업무 사용자 확인을 각각 구분해 기록한다. 회신이 없으면 「제공 여부 미확인」으로 기록하고, 필수 의존사항이면 진행을 보류한다
업무 처리 시험핵심 업무를 실제로 한 건 처리해 확인한다. 응답 코드 확인만으로 판단하지 않는다
복구 계획복구 가능 여부, 절차, 소요시간, 복구 불가 항목, 복구 결정자를 사전에 확정한다
전환 직전 재확인착수 미팅 이후 조건이 바뀔 수 있다. 전환 직전에 검증 결과를 다시 확인하고 승인 기록을 남긴다
전환 후 관찰관찰 기간, 이상 판단 기준, 연락 체계, 임시 조치 해제 조건을 정한다
승인 기록전환·종료 승인자의 이름과 승인 일시를 기록한다
